00 — Overview

A live simulator for a trust-aware edge orchestrator: nodes are scored on task success rate, CPU availability, latency, and uptime; an asymmetric update rule (reward small, punish hard) quarantines misbehaving nodes before they can cause lasting damage. This page runs the actual simulator on every request — nothing here is precomputed.

02 — Experiment A

Threshold Sensitivity

Sweeps the trust threshold and plots overall task success rate — computed live, not a static image. Success rate rises gradually as the threshold increases (a low threshold measurably costs you, since misbehaving nodes keep getting some traffic for as long as they stay eligible), then falls off a cliff once the threshold exceeds what real hardware can reach and the eligible node pool collapses. Not the paper's symmetric bell curve, but a genuine sensitivity curve rather than a flat line.

03 — Experiment D

Resilience to Saturation

Fixes a 500-node population and sweeps the fraction of malicious nodes from 0% to 50%, comparing overall success rate between the trust-based scheduler and the random baseline.

04 — Reference

How It Works

Trust score

τ = 0.35·SR + 0.25·CPU + 0.20·Latency + 0.20·Uptime, seeded per node from its hardware profile.

Asymmetric update

+0.025 per success, −0.045 per failure — reward slowly, punish hard, so misbehaving nodes can't linger.

Quarantine

Once τ < 0.55 a node is permanently excluded — an absorbing state, proven via a discrete-time Markov chain.

Full equations, design-choice writeups, and the honest-results discussion (including why this simulation's Experiment A differs in shape from the paper's) are in the repo README.
